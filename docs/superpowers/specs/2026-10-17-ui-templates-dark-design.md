# 深色多视图界面、Shell 模板与日志可读性改造

日期：2026-10-17（Asia/Shanghai）  
状态：用户已确认会话设计，等待书面规范审阅

## 1. 目标与成功标准

当前界面把服务控制、绑定编辑、时间参数和诊断日志堆在同一个页面；长命令和长日志会挤压布局，Shell 命令也无法复用。此次改造的目标是让常用操作有明确入口，让长文本始终被限制在自己的容器中，并把成功保存过的 Shell 命令自动沉淀为可复用模板。

成功标准：

- 用户可以在概览、绑定、Shell 模板、诊断四个视图之间清楚导航。
- 绑定页面仍支持任意长度组合，新增、编辑、删除和保存行为保持现有语义。
- 成功保存配置后，绑定中的 Shell 命令按命令内容去重自动进入模块模板库；模板可重命名、编辑、删除并应用到绑定编辑器。
- 任何单条命令、日志消息或原始 JSON 都不会改变页面整体宽度；长内容在局部换行、展开或滚动。
- 界面固定使用深色主题，桌面和 390px 窄屏都能完成核心流程。
- 现有 `config.conf`、守护进程输入协议和服务脚本行为保持兼容。

不在本次范围内：修改按键识别规则、增加命令沙箱、远程同步模板、改变日志文件格式或增加真机专属行为。

## 2. 页面结构与导航

继续使用单个 Vite/React 应用，不引入 React Router。应用内部使用受控的 `activeView` 切换视图，这样 KernelSU WebView 不依赖 URL 路由恢复，也不增加新的运行时依赖。

桌面宽度下显示左侧导航栏，窄屏下显示底部导航栏；两者使用相同的四个入口：

### 概览

显示服务运行状态、绑定数量、模板数量和最近一次执行结果。提供启动/停止服务、新增绑定、打开诊断三个主要操作。只读取并展示最近少量日志摘要，不在首页渲染完整日志。

### 绑定

保留动态组合编辑器和时间设置。绑定以卡片显示组合说明、编码、命令摘要和编辑/删除操作。长命令显示有限预览，完整内容在局部展开区域中查看。时间设置移动到页面底部的高级区域。

绑定草稿只存在于当前页面状态。只有“保存配置”成功后才触发模板收录；取消或保存失败不会写模板库。

### Shell 模板

显示自动收录的模板列表，支持搜索、选择、重命名、编辑命令、删除和“应用到绑定”。模板编辑使用与绑定编辑器相同的命令校验，并显示 UTF-8 字节计数和 root 权限提示。应用模板只填入绑定草稿，不直接写 `config.conf`。

### 诊断

解释日志和原始事件分成两个标签。解释日志使用结构化行显示时间、结果、组合和命令摘要；点击一行后在行内展开完整命令。原始 JSON 放入具有固定高度和内部滚动的代码区域。空日志、读取失败和可解析行不足分别显示明确状态。

## 3. Shell 模板数据流

模板文件路径固定为：

```text
/data/adb/modules/oplus-sidekey/templates.json
```

文件只由 WebUI 读写，守护进程不依赖它。格式为 UTF-8 JSON 数组：

```json
[
  {
    "id": "stable-id",
    "name": "返回桌面",
    "command": "input keyevent 3",
    "updatedAt": 0
  }
]
```

约束：

- `command` 必须通过既有单行、无 NUL、最多 511 个 UTF-8 字节校验。
- `name` 为空时恢复为生成名称；名称只用于显示，不进入守护进程配置。名称拒绝换行和 NUL，最多 128 个 UTF-8 字节。
- 相同 `command` 只保留一个模板；自动收录时保留已有名称和 ID，只更新时间。模板文件中已经存在重复命令时按文件顺序保留最后一条。
- 手动编辑命令时如果与其他模板重复，阻止保存并提示使用已有模板，避免两个 ID 指向同一命令。
- 模板库沿用 64 KiB 文件上限；超过上限时阻止本次模板写入并显示错误，不影响已保存配置。
- 读取失败、JSON 损坏或字段校验失败时，不覆盖当前内存模板；页面显示可重试状态。
- 写入沿用现有安全方式：JSON 序列化后 UTF-8 编码，使用 base64 传给已有 Shell bridge，写入同目录临时文件并 `mv` 替换目标文件。
- 首次读取文件不存在时视为空数组；首次成功保存绑定命令时创建文件。

保存配置成功后的顺序为：解析服务返回成功标记 → 更新磁盘配置指纹 → 合并当前配置中的命令到模板集合 → 写模板文件。模板写入失败只提示模板同步失败，不回滚已经成功保存的 `config.conf`。

## 4. 日志和长文本布局

守护进程日志文件仍保持现有格式和 200 行读取范围。本次重点修正前端布局：

- 所有日志和命令容器设置 `min-width: 0`，长单词、路径和 Shell 参数使用 `overflow-wrap:anywhere`。
- 解释日志每行限制摘要宽度；完整 `action` 在本行展开，不让它撑开卡片或页面。
- 原始事件区域使用固定最大高度和 `overflow:auto`；JSON 保持等宽字体，横向滚动只发生在该区域。
- 绑定卡片和模板卡片使用同一套长命令预览组件，避免两个页面出现不同溢出行为。
- 日志读取仍按需执行，防止打开页面时一次性加载完整文件。

## 5. 视觉与交互

主题固定为深色：深蓝黑背景、分层卡片、蓝紫主色、绿色成功、琥珀警告和红色错误。`sonner`、Radix 对话框、输入框、按钮、代码区域和导航都使用同一组颜色变量。焦点环保持高对比度，按钮在窄屏下不能只依赖图标，保留可读文字或无障碍名称。

页面状态至少包括：初始加载、配置读取失败、服务状态未知、未保存、保存中、已保存、应用请求失败、模板读取失败、模板写入失败和日志读取失败。执行中的操作继续使用现有互斥标记，避免模板、保存、启停请求并发覆盖。

## 6. 代码边界

- `App.tsx` 负责视图导航和共享页面状态，不再直接承担所有日志行布局。
- 新增模板模块负责模板类型、校验、去重、JSON 解析/序列化和 Shell bridge 命令生成。
- 新增长文本/日志展示组件负责摘要、展开和局部滚动；绑定和模板页面复用它。
- 现有 `config.ts`、`daemon.ts`、`log.ts` 继续作为格式和命令边界，不复制校验逻辑。
- 现有守护进程日志实现只在测试证明有必要时调整；优先通过 UI 容器解决页面溢出。
