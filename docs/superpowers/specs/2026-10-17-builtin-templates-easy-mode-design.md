# 内置模板、新手模式与易用性优化

日期：2026-10-17  
状态：用户要求“内置一些模板方便用户使用，让普通用户也能用明白，做有用的优化，检查代码并自行验证后打包”。用户把细节决定交给实现方，以下取舍均为实现方的判断，并在交付说明中列出。

## 1. 目标

当前界面面向会写 Shell 的用户：新增绑定时必须手写命令，模板库只收录用户自己保存过的命令，新装模块时模板库是空的。普通用户不知道该写什么，也不清楚“短按／长按／连按间隔”的实际效果。

成功标准：

- 不会 Shell 的用户可以只靠点选完成“选组合 → 选动作 → 保存”，全程不需要手写命令。
- 内置一组经过筛选、在 Android 10+ / ColorOS 上以 root 执行可用的常用动作，按类别浏览和搜索。
- 提供“一键方案”，空配置时一次套用一组推荐绑定；套用只改草稿，保存后才生效，覆盖已有组合前必须确认。
- 绑定卡片、诊断记录用动作名称说话（“截屏”“打开应用：com.tencent.mm”），而不是只显示原始命令。
- 未保存的修改在任意页面都能看到并直接保存。
- 现有 `config.conf` 格式、守护进程协议、`templates.json` 格式和全部既有行为保持兼容。

不在范围内：修改按键识别算法、命令沙箱、手电筒等无通用 Shell 命令的厂商私有功能。

## 2. 内置动作（presets）

纯前端常量，不写入任何文件，守护进程不感知。每个动作：`id`、`name`、`description`、`category`、`command` 或带参数的 `build(values)`。

| 类别 | 动作 | 命令 |
|---|---|---|
| 系统 | 返回桌面 / 返回上一页 / 最近任务 | `input keyevent 3` / `4` / `187` |
| 系统 | 熄屏锁定 | `input keyevent 223` |
| 系统 | 截屏 | `input keyevent 120` |
| 系统 | 下拉通知栏 / 快捷设置 | `cmd statusbar expand-notifications` / `expand-settings` |
| 系统 | 语音助手 | `input keyevent 219` |
| 媒体 | 播放/暂停、下一首、上一首、音量加、音量减、静音切换 | `input keyevent 85/87/88/24/25/164` |
| 开关 | 勿扰、Wi‑Fi、蓝牙、自动旋转（按当前状态切换） | `settings get` 判断后 `cmd notification set_dnd` / `cmd wifi set-wifi-enabled`（回退 `svc wifi`）/ `cmd bluetooth_manager`（回退 `svc bluetooth`）/ `settings put`；Wi‑Fi、蓝牙按 `1|2` 视为开启（含飞行模式下开启），需真机验证 |
| 应用 | 打开相机、录像 | `am start -a android.media.action.STILL_IMAGE_CAMERA` / `VIDEO_CAMERA` |
| 应用 | 支付宝扫一扫 / 付款码 | `am start -a android.intent.action.VIEW -d 'alipays://platformapi/startapp?saId=10000007'` / `20000056` |
| 应用 | 打开指定应用（参数：包名） | `monkey -p <包名> -c android.intent.category.LAUNCHER 1` |
| 应用 | 打开网址（参数：链接） | `am start -a android.intent.action.VIEW -d '<网址>'` |

参数规则：包名必须匹配 Java 包名格式；网址必须是 `http://`/`https://` 或带 scheme 的单行文本，用单引号安全转义。生成的命令仍走既有 511 字节、单行、无 NUL 校验。包名输入框可“读取已安装应用”（`pm list packages -3`）作为候选。

`describeCommand(command, templates)` 把命令反查为显示名：精确匹配内置动作 → 参数动作模式匹配 → 用户模板名称 → “自定义命令”。

## 3. 一键方案（packs）

| 方案 | 单击 `0` | 双击 `00` | 三击 `000` | 长按 `1` |
|---|---|---|---|---|
| 日常效率 | 截屏 | 打开相机 | — | 勿扰切换 |
| 音乐控制 | 播放/暂停 | 下一首 | 上一首 | 静音切换 |
| 单手导航 | 返回上一页 | 最近任务 | — | 返回桌面 |
| 扫码支付 | 支付宝扫一扫 | 支付宝付款码 | — | 打开相机 |

`applyPack(bindings, pack)` 返回新草稿和将被替换的组合列表；有替换时界面先列出再要求确认。套用后显示“未保存”，不自动写盘。

## 4. 界面改动

- **概览**：无绑定时显示“三步上手”和“套用推荐方案”；新增“常见问题”折叠区（短按/长按、为什么单击有延迟、如何确认生效、命令安全、手电筒说明）。
- **绑定编辑器**：快捷组合按钮（单击、双击、三击、长按、短按+长按）+ 原有逐步编辑；“选择动作”面板（类别、搜索、参数表单）自动填入命令；仍保留“Shell 命令”文本框供高级用户修改；组合与已有绑定互为前缀时提示等待延迟；“试运行”按钮立即执行一次命令并显示结果（明确提示会真实执行）。
- **绑定页**：卡片显示动作名称；新增“一键方案”入口；时间设置增加“灵敏 / 标准 / 从容”三档预设。
- **模板库**（导航名由“Shell 模板”改为“模板库”）：标签页“内置动作”与“我的模板”；内置动作可直接“使用此动作”。自动收录时，命中内置动作的命令以动作名称命名，而不是“模板 N”。
- 自动收录只收录自定义命令和带参数的动作（如“打开应用：com.xx”）；无参数内置动作已在“内置动作”中，不重复收录。
- **试运行**：`timeout 10 sh -c '<命令>'`，与保存、启停互斥；退出码 0 但输出含 `Error`/`Exception` 时按失败提示。
- **全局**：有未保存修改且不在绑定页时，顶部显示提醒条和“保存配置”按钮。
- **诊断**：解释记录显示动作名称。

## 5. 模块与构建

- `customize.sh`：KernelSU 升级时 `$MODPATH` 指向 `modules_update`，原逻辑总会用默认配置覆盖用户配置和模板。改为优先从 `/data/adb/modules/oplus-sidekey/` 迁移 `config.conf` 与 `templates.json`。
- `module.prop`：版本 0.2.0 / versionCode 2，描述更新。
- `daemon/CMakeLists.txt`：主机未安装 libevdev 时回退编译 vendored libevdev，使 CTest 在无系统依赖的环境可运行。
- 守护进程 C 运行代码不改动，`module/bin/oplus-sidekey` 保持原二进制。

## 6. 验证

- 新增 `presets.test.ts`：命令构造、参数校验与转义、反查、方案套用与冲突。
- 扩展 App/编辑器/模板库测试：动作选择填入命令、方案套用确认、全局保存条、模板库标签、试运行、按动作名收录。
- `vitest`、`tsc -b`、`oxlint`、`vite build`；C 端 CTest 12 组；模块脚本 `sh -n`；浏览器检查桌面与 390px 窄屏；打包后核对 ZIP 条目与 `module/` 一致。
- 最终独立代码审查。真机行为（各命令在具体 ROM 上的效果）需设备验收。
