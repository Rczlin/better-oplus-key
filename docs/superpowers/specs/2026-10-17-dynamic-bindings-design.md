# 动态按压绑定与操作体验改进

日期：2026-10-17（Asia/Shanghai）  
状态：待用户书面审阅

## 1. 已确认的目标

面向会使用 Shell 命令的用户，让侧键配置更直观，并审查现有实现及改造后的代码。

用户已确认：

- 保留命令配置，改善布局、术语、说明和操作反馈。
- 用户按需创建、编辑和删除短按／长按组合；支持四次及更多按压。
- 按已配置的组合判断触发时机：存在更长的后续组合时等待，否则完整匹配后立即执行。

验收重点是能完成“创建长组合 → 保存 → 正确识别与执行”，同时保持旧配置的命令内容、输入事件时序和失败保护。

## 2. 页面与操作流程

页面依次展示侧键运行状态、已创建的绑定，以及可展开的时间设置和诊断记录。

1. “新增绑定”打开编辑器。通过“短按”“长按”按钮依次组成手势，可以撤回最后一步或清空；组合以文字和顺序标记展示，同时提供编码对照。
2. 填写单行 Shell 命令。编辑器说明短按／长按的含义、命令字节限制，以及命令以 root 权限执行的事实。
3. 添加后，主页显示该组合及命令。已有绑定可以编辑、删除；重复组合在编辑器中明确报错。
4. 修改先保留在页面草稿中，点击“保存配置”写入并请求运行中的服务应用。页面明确显示未保存、保存中、已保存以及应用请求失败等状态。
5. 读取配置失败时禁止覆盖；支持重试。保存和启停过程中禁用冲突操作，避免连续点击造成并发请求。
6. 状态未知时提供状态查询／重试，不把未知状态当成已停止。诊断记录按需读取，读取失败显示原因。

时间设置沿用默认 300 毫秒、范围 100–800 毫秒：

- “长按时长”：按住达到该时长后松开，计为一次长按。
- “连按间隔”：上一按松开后，在该间隔内再次按下会继续当前组合；达到间隔边界时，上一组合结束。

复用现有 React、shadcn/ui、Radix、Lucide 和 Sonner。编辑器使用 Radix 的对话框能力处理焦点和键盘操作。

## 3. 识别规则

短按、长按仍分别编码为 `0`、`1`。每次按压在松开时完成分类，使用输入事件的单调时钟时间戳。

| 配置与输入 | 预期行为 |
|---|---|
| 只配置单击 `0`，输入一次短按 | 松开立即执行 |
| 配置 `0` 和 `00`，输入一次短按并停顿 | 连按间隔结束后执行 `0` |
| 配置 `0` 和 `00`，间隔内输入两次短按 | 第二次松开立即执行 `00`，本次不执行 `0` |
| 配置 `0000`，输入四次连续短按 | 第四次松开执行 |
| 配置 `0` 和 `001`，输入 `00` 后停顿 | 整个输入未完整匹配，不执行命令 |
| 当前输入已不是任何配置的前缀 | 本段输入失配，等待连按间隔结束后开始下一段 |
| 叶子组合已执行，继续按键 | 作为新的组合识别 |

不完整或失配的输入沿用完整匹配原则，不回退执行某个较短命令，也不把失配后的尾部重新解释成新手势。诊断记录区分已执行、未匹配和执行失败。

已有一至三次组合仍可直接读取；实际触发时机遵循上述用户选择的智能规则。

## 4. 配置与内存模型

继续使用模块内的 `config.conf` 和 `组合=命令` 格式。例如：

```ini
keycode=735
long_press_ms=300
window_ms=300
0=echo single
0000=echo four
01001=echo mixed
```

前端使用动态绑定集合。C 端仅为配置中的条目分配存储，使用成熟的 uthash 处理键值查找和删除；前缀判断遍历实际绑定，不生成全部可能组合。

- 依赖固定到 uthash `v2.4.0`，上游提交 `a49bed0b4abb7dff16c73906dcdc8a9718d582d2`，保留许可证。
- 组合长度和条目数由实际配置决定。沿用现有整份配置 64 KiB 的资源上限，前后端统一检查；编辑器及时显示超限错误。
- 命令仍最多 511 个 UTF-8 字节，完整保留引号、等号、中文等内容。拒绝会破坏单行格式的换行和 NUL 字符。
- 同一组合在原始配置文件中重复出现时，前后端统一为最后一条生效；末条空命令表示解除该绑定。界面阻止创建重复组合。
- 数值严格解析并检查溢出和范围。时间参数须为 100–800 的整数；键码须为 1–767 的整数（当前 Linux 头文件的 `KEY_MAX` 为 767）。前端保存时保留读取到的有效键码。
- 配置读取必须完整；解析、读取或内存分配失败时保留上一份有效配置。
- 配置对象拥有绑定内存，提供明确的初始化和释放过程。uthash 启用可恢复的分配失败处理。

上游依据：[uthash 源码与标签](https://github.com/troydhanson/uthash/tree/v2.4.0)、[用户指南](https://troydhanson.github.io/uthash/userguide.html)。

## 5. 前后端衔接

- 状态机按配置中最长组合准备输入缓冲区；输入失配后不继续增长缓冲区。
- 运行层向状态机提供精确匹配与后续组合信息，命令仍由现有子进程方式执行。
- 配置加载先完成新绑定和识别资源的准备，再切换活动配置。热加载成功时清除进行中的手势，避免同一段输入跨越两份配置；失败时保留原有配置和可用资源。
- 输入同步丢失、重复边沿、批量读取延迟等已有保护继续保留。
- 使用 Linux `ppoll` 和信号掩码把状态检查与等待衔接起来，消除停止／重载信号在检查后、休眠前到达造成的丢失唤醒；子进程通知在回收开始前清除，保留回收期间的新通知。
- 通过模块目录内的生命周期文件锁保证只有一个活动实例；只有实际拥有 PID 文件的实例才负责删除它。锁文件遵循现有模块目录的清理范围。
- 运行期间改变键码需要停止后重新启动。热加载遇到键码变更时拒绝本次切换、保留整份原配置并写明确诊断，避免新键码与旧输入设备混用。
- 命令运行记录保存完整组合，覆盖运行中子进程记录和日志格式；前端日志解析支持更长组合。
- 保存沿用同目录临时文件、完整写入后替换原文件的方式。发送应用信号成功仅表示请求已发出，页面不将其表述为底层已确认加载成功。

## 6. 现有代码审查发现

已通过最小复现确认：

1. **重复绑定不一致**：`0=echo first` 后再写 `0=echo second`，前端显示第二条，C 运行层查找第一条。统一解析规则，并补跨端回归。
2. **C 数值校验缺失**：`long_press_ms=0`、`window_ms=-1` 被接受；`4294967596` 被截成 `300`。补严格转换、溢出及范围校验，并验证失败保留旧配置。
3. **信号丢失唤醒**：主循环检查信号标记后进入 `poll`，两步之间收到的信号可能让程序在空闲时继续无限等待。用原子信号等待修复，并测试空闲时停止／重载。
4. **PID 所有权错误**：并发启动时，失败的实例可能删除已经成功启动的实例的 PID 文件。增加生命周期互斥和所有权检查，并测试第二次启动不破坏第一个实例的控制文件。
5. **子进程通知被覆盖**：回收结束时清除通知，可能覆盖回收过程中刚到达的新通知。调整清除时机并测试该竞态。
6. **键码热加载与设备不一致**：现有热加载可替换键码，却继续使用原来独占的设备。明确为需要重启的变更，防止应用不一致配置。
