# 动态绑定改造后的独立代码审查

日期：2026-10-17（Asia/Shanghai）  
范围：动态绑定改造后的工作区，包括原有未提交修改、新增守护进程测试、WebUI、模块脚本和安装包。

## 审查结论

**可合入。未确认 Critical、Important 或 Minor 级缺陷。**

独立审查通读了生产配置、FSM、输入接入、守护进程生命周期、前端编辑器、KernelSU 桥接脚本、全部新增 C 测试和 vendored uthash，并针对所有权、热加载、信号、PID 和状态反馈做了边界检查。

| 基线问题 | 当前实现证据 |
|---|---|
| 重复绑定含义不一致 | 配置更新时唯一组合末条生效；空命令删除绑定；前端和运行层使用同一规则 |
| 数值溢出、范围缺失 | 严格十进制解析、`ERANGE` 检查和键码/时间范围检查 |
| 信号丢失唤醒 | 屏蔽信号后检查标记，由 `ppoll` 原子恢复掩码等待 |
| PID 所有权错误 | 生命周期锁、成功写入后的所有权标记，以及删除前的 PID 内容核对 |
| 子进程通知被覆盖 | 回收前清除标记，`waitpid` 遇 `EINTR` 重试 |
| 键码热加载不一致 | 运行中拒绝键码变更，保留整份旧配置和 FSM |

## 边界检查

- 配置与 FSM 先准备后切换；短读、NUL、解析失败和 OOM 都不会销毁活动资源。
- FSM 支持任意配置长度；失配后停止追加并等待当前按压段结束，叶子执行后正确重置。
- 子进程记录拥有自己的组合和命令副本，热加载不会使退出日志引用旧配置内存；日志缓冲区按实际长度分配。
- 保存、启停和诊断读取都具备状态反馈与并发保护；未知服务状态、读取失败和应用请求失败会分别显示。
- 独立 OOM 故障注入覆盖 512 条绑定、1030 个分配点（包括哈希扩容）；ASan/UBSan 下未发现内存错误，失败时旧配置保持有效。
